## Planner decisions (Claude's discretion: no CONTEXT.md and no RESEARCH.md for this phase)

- **PD-60 Freeze record: moved to Plan 04-01.** The freeze (what is hashed, `write --force` guard, `check --against-git`, reversibility `costly`) is written and tested there, after `make strict` and `make test` and before any timing run. This plan only consumes it: `freeze.check()` in every preflight and postflight and `freeze.binary_sha256()` for the binary hash, which is machine specific and therefore lives in `session.json` and the engine manifest, not in the tracked freeze.
- **PD-61 TP3 out-of-tree build with TP3's own flags.** `tp3_rerun.py` parses `TP3/Makefile` at run time (CXXFLAGS and CORE_SRC plus `src/main.cpp`), so the flags are TP3's literally, not a copy. Each source is compiled with the working directory set to `TP3/` (so `-Isrc/include` resolves) and absolute `-o` paths under `ejercicio2/build/tp3_bench/`, then linked into `ejercicio2/build/tp3_bench/tp3`. make is never invoked in TP3 (its `tp3` target would rewrite `TP3/build/` and `TP3/tp3`). The compiler is the CXX that make resolves for TP4 (`make -s --no-print-directory -C ejercicio2 print-toolchain`), so both engines come from the same compiler; `codegen_flags_equal` compares both flag lists without `-I`/`-W` tokens.
- **PD-62 TP3 benchmark re-run unchanged.** Official invocation: TP3's defaults (N 25..200, seeds 1..100, tmax 30, empty table) are exactly TP3 1.1, so only `--binary`, `--raw`, `--summary` and `--plot` are passed. Extension: one invocation per N in `TP3_EXT_N = (300, 400)` with seeds 1..10, to locate the crossover (planner extrapolation: TP3 grows about N^3.3 from 0.47 s at N = 200, so about 1.8 s at 300 and 4.7 s at 400; TP4 grows about N, about 1.4 s at 200 and 2.9 s at 400 at dt*, so the curves cross between N = 300 and 400). An extension invocation that fails with TP3's generator message is recorded as `generator_limit` and the session continues (Q2 default: the TP3 curve stops at its generator limit, disclosed); an official-invocation failure aborts the session. Subprocess environment: `PYTHONDONTWRITEBYTECODE=1`, `MPLCONFIGDIR` under `build/tp3_bench/mpl`, working directory `build/tp3_bench`.
- **PD-63 TP4 sweep.** x0 = r = 0.0175 m (obstacles in contact, the enunciado's 2.1b case; TP3 1.1 used an empty table, Q3 default: compared as is and disclosed), tf = 30 s, dt = DT_STAR, N = 50..650 step 50 (lattice capacity at x0 = r is 666, Phase 2), seeds 1..10 (common seeds, 2.4a reuses them), `init = "lattice"` explicitly for every N (one method across the curve; `auto` would switch at N = 400), trajectory off, stop none, every = `every_for(DT_STAR, 0.01)` = 200 (no frames are written; keeps names aligned with 2.1a), timing = True, workers = 1, per-run timeout 900 s, seed-major order like TP3's `collect` so drift spreads over N.
- **PD-64 Session protocol.** One command, one process, serial: preflight -> TP3 build -> TP3 official -> TP3 extensions -> TP4 sweep -> postflight -> aggregation and figures. Preflight failures write nothing. A failure after preflight writes `session.json` with `status: aborted` and the failing block, exits 1, and the next official attempt refuses until the user moves `data/timing` aside (a session never reuses runs from another session). The official mode never deletes; `--smoke` deletes only the resolved `data/timing_smoke` (containment-checked). Paths in records are relative to `TP4/`; no hostname or user name is stored.
- **PD-65 Timed quantity.** Both curves use the engine-internal `simulation_ms` (steady_clock around the physics loop; generation, process start and file opening excluded; TP4's conversion log and TP3's goals log inside, both buffered). Seconds on the figure; sigma is the sample standard deviation on both sides (TP3 uses `statistics.stdev`, TP4 `plot_style.mean_and_sigma`).
- **PD-66 Figures.** `timing_vs_N`: one log-log axes, two series with sigma bars and markers, x label "Número de partículas N", y label "Tiempo de ejecución (s)", legend "Paso temporal fijo (TP4, dt = 5×10⁻⁵ s)" and "Dirigida por eventos (TP3)" (dt rendered from DT_STAR), slopes as text in axes fraction. `cost_per_particle_step`: TP4 only, cost = simulation_ms / 1000 / (N * final_step), y label "Costo por partícula y por paso (s)". Slopes are least squares on (log N, log mean time); the crossover is the first common N bracket where the sign of log(t_TP3/t_TP4) changes, with a log-log linear interpolation; both are printed and stored in `scaling.json`, never drawn as lines.
- **PD-67 Compute budget (from Phase 2/3 measurements).** TP4: the sum of N over the grid is 4550, times 600 000 steps times 10 seeds = 2.73e10 particle-steps: 5.6 min at 12.2 ns per particle-step (Phase 2, M4 Pro, serial) or 8.2 min at 18 ns (research prototype on the Ryzen/WSL target); the slowest run (N = 650) about 7 s. TP3 official: 0.73 s per seed (old means) times 100 seeds, about 75 s plus process starts. TP3 extension: about 65 s. TP3 build: under a minute. Session total about 10 to 12 minutes; disk about 3 MB. `BUDGET_NS_PER_PARTICLE_STEP = 18.0` drives the estimate printed at session start. Smoke: under a minute including the TP3 build.
