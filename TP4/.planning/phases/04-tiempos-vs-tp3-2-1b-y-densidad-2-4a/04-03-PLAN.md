## Planner decisions (Claude's discretion: no CONTEXT.md and no RESEARCH.md for this phase)

- **PD-70 Inputs by directory scan.** The run list is every subdirectory of the timing study whose name fully matches `N\d+_.+_seed\d+` (this excludes `tp3`, `figures`, `.partial` and `.failed` directories by construction); the engine manifest is not used because the runner rewrites it per batch. A `diverged.json` in a run directory is an error (a timing run at dt* must not diverge). `study_density.py` does not import `engine` (it defines `DATA_ROOT` the same way, `ejercicio2/data`), which makes the no-simulation rule checkable by an AST test.
- **PD-71 Validation.** obstacles on, x0 = 0.0175 (within 1e-12), init lattice, stop `tf` with both stop flags off, tf = 30 and final_time = tf (math.isclose), dt = DT_STAR (rel 1e-12), the same R and radius for all runs, summary.used = conversions.used, no duplicate (N, seed), at least `--min-seeds` seeds per N (10 for the official data, 2 for smoke and tests). A violation aborts the study with `error:` and the offending directory; nothing is silently skipped.
- **PD-72 Observables.** k90 = (9N + 9) // 10 (the engine's `conversionTarget90`, integer arithmetic, no floating threshold); t90 = conv.t[k90 - 1] if used >= k90; t100 = conv.t[N - 1] if used == N; Fu(30 s) = used / N, since a run ends at final_time = tf. Density rho = N / (pi R^2) in m^-2 from the header R, packing fraction phi = N r^2 / R^2 kept in the CSV; the x axis is rho with a secondary top axis in N (the 2.1b reader sees the same N grid).
- **PD-73 Censoring rule (Q7 default).** Status per N and threshold: `all` (every run reached it) -> mean and sample sigma; `partial` -> mean NaN, lower bound mean(min(t_i, tf)) drawn as a hollow marker without a bar; `none` -> nothing on the time figure. Fu(30 s) mean and sigma and the success fractions are always reported, so a censored point is still visible in the second figure. Q7 (is Fu(30 s) plus the success fraction acceptable when t100 is not reached at tf = 30 s?) stays open with the docentes; this is the documented default.
- **PD-74 Optimum.** argmin of <t90> (and separately <t100>) over complete points; `edge` = the minimum sits at the smallest or largest complete N; `distinct` = |mean - neighbour mean| > sqrt(sigma^2 + sigma_neighbour^2) for every complete grid neighbour (False when there is none). Printed as `optimum: t90 N=... rho=... ...` and stored in `optimum.json`; the figure marks it. A minimum that is at the edge or not distinct is reported as such, never as "the optimal density".
- **PD-75 Lattice start.** All 2.1b runs start from the jittered lattice (Phase 2 PD-15), so at high density the conversion times include caging from an ordered start; the README states this next to the results (Q4 default: no melting pre-run, which would need an engine change after the freeze).
