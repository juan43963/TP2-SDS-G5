## Planner decisions (Claude's discretion: no CONTEXT.md and no RESEARCH.md for this phase)

- **PD-80 Target machine.** The roadmap and PROJECT.md fix WSL Ubuntu-24.04 on the AMD Ryzen 7 9800X3D (g++ 13.3, the toolchain TP3 was built with). Verified while planning: WSL Ubuntu-24.04 running, g++ 13.3.0, python3 with numpy 2.5.1 and matplotlib 3.11.1, 16 logical CPUs. If the group chooses another machine, the comparison is still valid because TP3 and TP4 are built with the same compiler and measured in the same process there, and session.json records the host; the README must state the machine actually used.
- **PD-81 Why a human launches it.** Gate 5 requires an idle machine; an agent cannot close the user's programs, keep the laptop on AC power or stop other agents. Everything else (readiness, verification, replot, density, documentation) is automated around the checkpoint.
- **PD-82 Readiness tracer.** The first task runs the whole chain at smoke scale on the session toolchain, including `make strict` with g++ 13.3 (Phase 2 left the WSL strict/test gate to the user, 02-03 coverage D5), so the long session cannot fail on a toolchain or wiring problem.
- **PD-83 Budget (Plan 04-02 PD-67).** About 10 to 12 minutes in total: TP4 5.6 to 8.2 min (2.73e10 particle-steps at 12.2 to 18 ns), TP3 official about 75 s, TP3 extension about 65 s, TP3 build under 1 min. More than 45 minutes means something is wrong (load, wrong dt, throttling).
- **PD-84 Results documentation.** Values in the README are copied from the scripts' printed tables (never retyped from memory) and rounded to the first significant figure of sigma (guide 1.10); the section cites session.json's `finished_utc` and the first 12 hex digits of the freeze digest so every number is traceable. Outliers are reported, never removed.
- **PD-85 Reversibility.** The official dataset feeds the slides; redoing it costs another 12-minute session and a new review but no migration: `costly` on Task 2 (flagged, no decision checkpoint).
