## Planner decisions (Claude's discretion: no CONTEXT.md and no RESEARCH.md for this phase)

- **PD-60 Freeze record** (moved here from the 2.1b pipeline plan, now Plan 04-02, so the freeze is its own wave-1 plan). The fingerprint covers every `.cpp`/`.h` under `ejercicio2/src` (selftest and oracle included: the roadmap freezes `src/` as a whole), hashed with CRLF -> LF normalisation, plus the literal value of the Makefile `CXXFLAGS` line (the rest of the Makefile keeps changing in this phase, so it is not hashed). The binary hash is machine specific, so it is not in the tracked freeze: Plan 04-02 records it in `session.json` and compares it with the engine manifest, before and after each session. `freeze.py write` refuses to overwrite a freeze with a different digest unless `--force` (re-freezing invalidates 2.1b) and is a no-op on an unchanged tree (keeps `frozen_utc`). `check --against-git HEAD` compares the frozen hashes with the committed blobs, so an uncommitted engine edit can never slip into the freeze. Every function that reads the tree takes `root=EJ2_DIR`, so the tests run on temporary trees and never touch the real record. Reversibility: `costly` (any later engine change re-runs the 2.1b session, about 10 minutes, and every Phase 5 sweep; no migration).
- **PD-60b Git revision argument.** `check_against_git` rejects a REV that starts with `-` and resolves it with `git rev-parse --verify --quiet REV^{commit}` before any `git show`, so the user-supplied string can never be read as a git option.
