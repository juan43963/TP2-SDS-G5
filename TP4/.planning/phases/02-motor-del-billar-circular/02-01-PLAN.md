## Planner decisions (Claude's discretion — no CONTEXT.md for this phase)

- **PD-01 Integrator = original Verlet** (ENG-06; research SUMMARY conflict #3). Bootstrap r(−dt) = r0 − v0·dt + (dt²/2m)·F(r0) (Teórica 4 slide 14). Frame velocity = (r_{k+1} − r_{k−1})/(2dt), so frame k is written after r_{k+1} is computed. Open docentes question Q1; switching to Velocity Verlet is local to `simulate` and the trajectory is identical. Rated reversible.
- **PD-02 Wall force** = −k·ξ·n̂ with ξ = |r_i| + r − R, applied only when |r_i| > R − r. This is the enunciado's image-particle spring (r_img = (R + r)·n̂, recomputed every step) written in closed form; unlike the literal 2r − |r_img − r_i|, it stays restoring if a particle ever passes R + r at an exploding dt. The test oracle uses the literal image construction, which cross-checks the equivalence.
- **PD-03 Contact is strict ξ > 0** for forces and conversion: distance exactly 2r, or |r_i| exactly R − r, is no contact.
- **PD-04 Timed region** = from just before the bootstrap force evaluation to just after the loop, minus the time spent inside the frame sink. The conversion log is inside (TP3 timed its goals log too); generation and file opening are outside. Reported as `simulation_ms`, with `frame_io_ms` alongside.
- **PD-05 Versioned, self-describing outputs**: every file starts with a `# TP4_<KIND> 1` line carrying all run parameters, and ends with a `# END` trailer, so Phase 3 can reject truncated or drifted files (TP1 "no shared schema" anti-pattern). There is no separate static file; the parameters travel in every header. Rated costly: Phase 3 readers depend on it, and the version token makes a later change detectable.
- **PD-06 Defaults and limits**: N = 100, x0 = radius when `--x0` is not given, dt = 1e-4 s, tf = 10 s, every = 100 (dt2 = 0.01 s), seed = 1. Studies always pass dt explicitly; Phase 3 freezes DT_STAR. dt must divide tf (|K·dt − tf| ≤ 1e-9·tf), K ≤ 1e9, and frames·N ≤ 1e8 rows when the trajectory is on.
- **PD-07 Two early-stop rules**, both off by default and both recorded in every header: `--stop-when-all-used` (Nu = N) and `--stop-at-t90` (Nu ≥ (9N + 9)/10). The integer threshold avoids floating ceil(0.9·N). If both trigger on the same step, the reason is `t90`. Never used for 2.1b, which is a Phase 4 rule.
- **PD-08 Non-finite guard**: any NaN or infinite coordinate throws std::runtime_error. No silent repair.
- **PD-09 CIM**:
  - M = floor(2R/(2r)) = 29 cells per side, cell side 0.0351724 m ≥ 2r, over [−R, R]²;
  - head/next linked lists rebuilt every step;
  - half stencil {(0,0), (1,0), (1,1), (0,1), (−1,1)}, as in TP1 `computeCIM`;
  - bin index computed in double and clamped to [0, M−1] before the int cast. Clamping is monotone and moves an index by at most one per cell, so contacts stay exact even for particles outside the box.
- **PD-10 RSA**:
  - positions polar-uniform in the disk of radius R − r, rejected on any overlap (pair or obstacle, distance² < 4r²) using a 3×3-cell accelerator on the same M-grid;
  - at most 1e5 attempts per particle;
  - all positions are drawn first, then all velocity angles, from one `std::mt19937_64(seed)`. Generation never reads dt, tf or every, so 2.1a gets the same initial condition at every dt.
- **PD-11 Self-tests in ejercicio2's own `tp4_test`** (Plan 02-02). `ejercicio2/src/selftest.cpp` holds `main` and every billiard check, as `ejercicio1/src/selftest.cpp` does for the oscillator, with a verbatim copy of `test_support.h`. The O(N²) oracle (`src/tests/brute_force_forces.cpp` behind `src/include/brute_force_forces.h`) is test-only and never enters BILL_SRC or the zip.
- **PD-16 Standalone `ejercicio2/`** (the user's layout, stated in `ejercicio2/README.md`). It has its own Makefile, `.gitignore`, `.gitattributes` and `src/`, and shares or edits no file of `ejercicio1/`. Its Makefile copies `ejercicio1/Makefile`'s CXXFLAGS line, explicit-list convention, `-MMD -MP` pattern rule and `strict` gate verbatim, so the flags stay identical to TP3. Rated reversible: moving sources between directories changes no code.

(3) src/billiard/forces.cpp, the pure force kernel (PD-02, PD-03, PD-09):
- makeForceWorkspace sets:
  - M = cimGridSize;
  - cellSize = 2R/M;
  - head(M·M, −1);
  - next(particleCount, −1).
- computeForces(p, pos, ws, force, touching):
  1. Resize force to pos.size() and zero it. Clear touching. Refill head with −1.
  2. Throw std::invalid_argument naming the particle if any coordinate is not finite.
  3. Bin each particle. cx = static_cast<int>(std::clamp(std::floor((x + R)/cellSize), 0.0, M − 1.0)), and the same for cy. Push the particle at the head of the cell list via next/head.
  4. Pair loop over every cell. For each i in the cell, visit j later in the same list, then every particle of the neighbour cells at offsets (1,0), (1,1), (0,1), (−1,1) that lie inside the grid.
  5. Pair force:
     - d = pos[j] − pos[i];
     - if norm2(d) < 4·radius²: throw std::runtime_error naming i and j when norm2(d) == 0;
     - otherwise dist = sqrt, ξ = 2·radius − dist, f = (k·ξ/dist)·d, force[i] −= f, force[j] += f.

     This is F_i = −k·ξ·ê_ij with ê_ij = (r_j − r_i)/|r_j − r_i|, exactly the enunciado's law.
  6. When p.obstacles is set, for each i in ascending order and for each centre c in {(−x0, 0), (x0, 0)}:
     - d = c − pos[i];
     - if norm2(d) < 4·radius², add −(k·ξ/dist)·d to force[i] only (infinite mass).

     Push i onto touching once if it overlaps either obstacle. Ascending i keeps touching sorted.
  7. Wall, for each i with norm2(pos[i]) > (R − radius)²:
     - rn = sqrt;
     - ξ = rn + radius − R;
     - force[i] −= (k·ξ/rn)·pos[i].

     Add a why-comment: this is the spring against the image particle r_img = (R + r)·n̂, recomputed every call, written in closed form so it stays restoring past R + r.

  The wall and the obstacles never enter the grid.

(4) src/billiard/generator.cpp (PD-10):
- Anonymous-namespace `bool placeRsa(const BilliardParams&, std::mt19937_64&, std::vector<Vec2>& pos)`:

(5) simulate, in src/billiard/simulation.cpp (PD-01, PD-04, PD-08). Integer step clock: t = static_cast<double>(k)·dt, never accumulated by repeated addition.
1. Call validateParams and K = billiardStepCount. Require pos.size() == vel.size() == N (std::invalid_argument).
2. c = dt·dt/mass. ws = makeForceWorkspace. Allocate buffers prev, cur (= state.pos), next, force, vel scratch, used(N, 0) and touching.
3. start = std::chrono::steady_clock::now().
4. Bootstrap: computeForces(cur), then prev[i] = cur[i] − dt·v0_i + (0.5·c)·force[i].
5. For k = 0..K:
   - t = k·dt.
   - When k > 0, computeForces(cur). At k = 0, reuse the bootstrap forces and touching list.
   - For each i in touching with used[i] == 0: set used[i] = 1, increment usedCount, then call conversions(k, t, i) if the sink is non-empty.
   - next[i] = 2·cur[i] − prev[i] + c·force[i]. If a coordinate is not finite, throw std::runtime_error(`posicion no finita: particula <i> en el paso <k> (t = <t>); dt demasiado grande`).
   - When frames is non-empty and k % every == 0:
     - fill vel[i] = (next[i] − prev[i]) scaled by 1/(2dt);
     - take t0 = now(), call frames(k, t, cur, vel, used), and add now() − t0 to the frame-I/O accumulator.
   - finalStep = k.
   - std::swap prev with cur, and cur with next.
6. finish = now().
7. simulationMs = (finish − start in ms) − frameIoMs. finalTime = finalStep·dt.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| argv → billiard | Text typed by the user or passed by the Phase 3 runner; parsed into numbers, flags and output paths |
| billiard → filesystem | Writes frames, conversions and summary files at user-chosen paths, creating parent directories |

|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | parseBilliardOptions / validateParams (malformed numbers, NaN/inf, negative seed, int overflow of N, absurd R/radius) | low | mitigate | The strtod/strtoll/strtoull helpers require full consumption, errno == 0, finiteness and range. validateParams and billiardStepCount reject every invalid combination before any file is opened. | T-02-02 | Denial of service | Output volume, run length and memory (tiny dt, every = 1, huge tf, huge R/radius) | low | mitigate | K ≤ kMaxBilliardSteps (1e9) and frames·N ≤ kMaxFrameRows (1e8) when the trajectory is on. `--no-trajectory` for sweeps.
