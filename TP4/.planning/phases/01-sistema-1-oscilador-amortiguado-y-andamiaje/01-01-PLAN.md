## Planner decisions (Claude's discretion — no CONTEXT.md for this phase)

Numbers below were verified by the planner with a Python replica of all five schemes (scratch only, not in the repo).

- **PD-01 Velocity Verlet damping = implicit closed form** (OSC-04 allows implicit or predicted velocity). It is algebraically the same trajectory as implicit-centred Verlet (replica: max |Δr| = 9.5e-13 m at dt = 1e-3), but in velocity form, so it avoids the position-form round-off that bends Verlet upward below dt ≈ 1e-5. That contrast is itself a defensible result for the slide. Reversible (one function).
- **PD-02 Beeman = literal slide 20**: a(t+dt) evaluated once with (r(t+dt), v_pred) and reused as a(t) next step; a(−dt) from the Euler-backward state r(−dt) = r0 − v0·dt + ½a0dt², v(−dt) = v0 − a0·dt (replica slope 3.99–4.00, ECM 3.28e-10 at dt = 1e-3).
- **PD-03 Velocity Verlet position term = dt²/(2m)**. Slide 17 prints dt²/m; the replica shows that version collapses to slope 2, so it is a typo.
- **PD-05 Slope windows and tolerances**: Euler PC, Verlet, VV, Beeman over dt ∈ {1e-3, 5e-4, 2e-4, 1e-4}; Gear-5 over {5e-3, 2e-3, 1e-3}, because its ECM reaches the double-precision floor (~1e-28 m²) below dt ≈ 5e-4. Replica fit slopes: 1.95 / 4.00 / 4.00 / 4.00 / 10.09. Tolerances: [1.8, 2.2], [3.8, 4.2], [9.5, 10.5].
- **PD-06 ECM normalisation**: ECM = (1/N)·Σ_{k=1..N}(r_k − r_an(k·dt))² with N = tf/dt. Row k = 0 has zero error by construction.
- **PD-08 CLI**: a hand-rolled `--key value` loop with TP3's strtod validation helper. Note: TP3's `options.cpp` actually uses getopt_long (the research files say otherwise). TP4 follows ENG-01 ("sin getopt") and research conflict resolution #7.
- **PD-09 Flags**: `CXXFLAGS` identical to TP3 (`-std=c++20 -O2 -Wall -Wextra -Wpedantic -Wconversion -Isrc/include`; -Wpedantic is the same switch as the roadmap's -pedantic). `make strict` appends -Werror and is the zero-warning gate.
- **PD-10 Gear-5** is the fifth method `gear5` (DIF-01; docentes question Q9 still open, and Plan 01-02 can regenerate a four-method figure). α = {3/16, 251/360, 1, 11/18, 1/6, 1/60} (slide 29, velocity-dependent row). Initial derivatives come from differentiating the equation of motion (slide 30).
- **PD-11 Versioned text header** `# TP4_OSC 1`, so the Python reader can reject format drift (TP1 "no shared schema" anti-pattern).

- **OSC-08** (unclassified): the tolerances and windows of PD-05. The extra Gear-5 slope check [9.5, 10.5] goes beyond what OSC-08 asks for.
- **DIF-01** (unclassified): gear5 is included pending docentes Q9.

(3) src/oscillator/integrators.cpp:
- `parseMethod` accepts eulerpc, verlet, vverlet, beeman and gear5. Anything else throws std::invalid_argument with a message like `--method desconocido '<name>' (validos: eulerpc, verlet, vverlet, beeman, gear5)`. `methodName` is the inverse.
- `stepCount(dt, tf)` throws std::invalid_argument, embedding the offending value, when:
  - dt or tf is not finite or is ≤ 0;
  - dt > tf;
  - N = std::llround(tf/dt) gives |N·dt − tf| > 1e-9·tf (message like `--dt debe dividir a tf`);
  - N > kMaxOscSteps.

  Otherwise it returns N.
- An anonymous-namespace `integrateEulerPC` implements slide 23 literally (OSC-02; not Heun, not the slide-10 modified Euler):
  1. a = oscForce(r, v)/m;
  2. predict vp = v + a·dt and rp = r + v·dt (no dt² term);
  3. evaluate a1 = oscForce(rp, vp)/m, using BOTH predicted values;
  4. correct v ← v + a1·dt, then r ← r + v·dt (with the corrected v).

  Emit step 0 = (r0, v0) before the loop, and step k after each update.
- `integrate()` rejects steps < 0 and dispatches with a switch on Method. This task fills `Method::EulerPC`. Task 2 adds the other four cases to the same switch; until then they throw std::logic_error naming the method.

(4) src/include/osc_cli.h and src/oscillator/osc_cli.cpp. All declarations come from the `<interfaces>` block.
- `parseOscOptions` is a hand-rolled loop over argv[1..argc−1]. It uses no option-parsing library (PD-08; same `--key value` convention as ENG-01). It accepts:
  - `--method <name>`;
  - `--dt <s>`;
  - `--tf <s>`;
  - `--out <path>`;
  - `--help` or `-h`.
- Error handling:
  - a value flag at the end of argv throws std::invalid_argument(`<flag>: falta valor`);
  - any other token throws std::invalid_argument(`argumento desconocido '<tok>'; usar --help`). This also rejects positional arguments;
  - numbers go through an anonymous-namespace `parseDouble(const char* text, const char* flag)`, copied from TP3;
  - unless help was requested, a missing --method or --dt throws (`falta --method` / `falta --dt`), and stepCount(dt, tf) is called so invalid dt fails before any output.
- Do not add helpers that are never called. Unused functions in an anonymous namespace warn under -Wall and would fail `make strict`.
- `printOscUsage` prints Spanish usage:
  - the flags;
  - the five method names, each with its Teórica 4 slide;
  - the defaults;
  - the output format.
- `writeOscHeader` writes exactly the two comment lines of the format in `<interfaces>`.
- `writeOscRow` uses the format string `%.17g %.17g %.17g` followed by a newline (OSC-06). 17 significant digits round-trip a double. Fewer digits put an artificial floor near 1e-13 under the ECM (Pitfall 4).
- `runOscillator(o, out)`:
  1. builds OscParams with tf = o.tf and computes N = stepCount(o.dt, o.tf);
  2. writes the header;
  3. calls integrate with a sink that writes the row with t = static_cast<double>(step) * dt. Time always comes from multiplying the integer step, never from repeated addition (PD-06, OSC-06);
  4. flushes, then throws std::runtime_error(`error de escritura en la salida`) if std::ferror(out);
  5. returns N+1.
