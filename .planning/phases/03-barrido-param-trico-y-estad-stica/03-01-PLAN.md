  <context>
    SWEEP-04 requires the seed to be fixed explicitly per run, never by clock, and free of correlation between repeats (RESEARCH.md Pitfall 5). Once the report's error-bar/eta_c tables are built from data seeded under one formula, changing the formula later makes old and new sweep output non-reproducible-comparable -- the only reconciliation path is re-running the entire sweep. CONTEXT.md's "Claude's Discretion" section explicitly leaves the exact formula open (constrained only to: deterministic, documented once, correlation-free), so this is a genuine one-way choice, not a decision already made by the human.
  </context>
  <options>
    <option id="option-a">
      <name>Hash-based (sha256 of a formatted key string)</name>
      <pros>Cryptographic-strength decorrelation across near-identical float inputs (eta=0.30000001 vs eta=0.3 hash completely differently, so no accidental clustering across the eta grid); one line, no custom bit-packing or index-quantization logic to keep in sync with how the eta grid is actually built later.</pros>
      <cons>Not human-decodable from the seed value alone (can't eyeball a seed and infer which run produced it); depends on fixing float-to-string precision (e.g. rho/eta formatted to a stable number of decimals) so the same logical point always hashes identically.</cons>
    </option>
    <option id="option-b">
      <name>Arithmetic / bit-packed (large-prime combination of discretized indices)</name>
      <pros>Fully human-inspectable and hand-recomputable (rho index, a quantized eta index, model index 0/1, and repeat_index combined via distinct large-prime multiplication into a 64-bit integer); no dependency on float-repr/string-formatting stability.</pros>
      <cons>Requires an eta-quantization step whose bucket width must be kept in sync with however Plan 03-02's exploratory + fine eta grid is actually generated, adding an extra cross-file invariant; collision risk if the chosen index ranges are too small relative to the primes.</cons>
    </option>
  </options>
